# Marigold: A Self-Hosted Inference API for Open-Weight Models

Marigold is an AI inference API that runs on hardware you control. It serves open-weight models (Llama, Mistral, Qwen and many others) through OpenAI-compatible endpoints and through typed routes for sixteen kinds of model, from chat and embeddings to speech recognition and image generation. No request reaches OpenAI, Anthropic or any other model provider, and once its models are downloaded it runs with no network connection.

Bay Information Systems builds and maintains it, and releases it under the MIT licence. What follows covers how it is put together, how to install it, the API it exposes, what it runs, and where it fits.

## How Marigold is put together

Marigold runs as three layers on one host.

- **The platform** is shared by everything on the host: a model cache, a catalogue of the models in it, a job queue in Postgres, workers that run the models, and the API.
- **Applications** are a list of required models plus the code that uses them. They hold no weights.
- **Instances** are an application's code running in its own container, reaching the platform only through the API.

Because applications hold no weights, many of them share one cache and one GPU. A model downloaded once serves every application that declares it, and the same application runs unchanged on a laptop or on larger hardware. The model is the stable, shared layer and the applications are thin clients over it, the shape described in [models as a fat protocol](/library/45-fat-protocols-for-ai.html).

## Install and run

```sh
pip install bayis-marigold
marigold cache init
marigold registry add https://examples.marigold.run/
marigold application install chat
marigold cache populate chat
marigold application start chat
```

The first command installs the `marigold` CLI. The next two create the model cache and register the examples registry. `install` fetches the `chat` application, `cache populate` downloads the models it declares (the long step, and the only one that needs the internet), and `start` brings up the platform and the application: Open WebUI at `http://localhost:3000`, backed by a local instruct model. It needs Docker with Compose, the NVIDIA Container Toolkit for a GPU worker, and Python 3.12. The [getting started guide](https://marigold.run/docs/) has the full walkthrough.

## The API

**OpenAI-compatible endpoints.** `GET /v1/models`, `POST /v1/chat/completions` and `POST /v1/embeddings` accept unmodified OpenAI SDK clients, so Open WebUI, LangChain, LangGraph, Continue and code written for the OpenAI API point at Marigold by changing the base URL. Tool calls round-trip with their ids, and a requested JSON schema is checked after generation (a reply that does not match fails with a 422). Streamed responses arrive as correctly framed server-sent events, without token-level streaming.

**Typed routes.** Every model type has its own route, input and output, and requests go through a submit-and-poll path. Binary outputs (images, audio, video) are stored as objects and returned as references.

**Authentication** is left to the deployment. Marigold has none of its own: a gateway or identity provider in front of it authenticates callers and passes their identity through. ([AI inference infrastructure](/library/87-inference-infrastructure.html) covers the gateway.)

## What it runs

| Kind | Model types | Example uses |
|---|---|---|
| Language | instruct (chat), text embedding, text evaluation, text similarity | Question-answering over documents, extraction, classification, retrieval |
| Vision | image embedding, image-to-text, segmentation, depth | Describing and comparing images, visual inspection |
| Generation | text-to-image, text-to-video, image-to-video | Generating and regenerating images against a quality score |
| Audio | text-to-speech, speech recognition, text-to-audio | Transcription with timings, spoken output (including Welsh) |
| Evaluation | image evaluation, image-text alignment | Scoring outputs inside a pipeline |

Adding a model of an existing type needs no code: it goes in an application's `models.yaml` and the cache downloads it. The types combine into pipelines where one model's output conditions the next, such as quality-gated image generation (generate, score, regenerate until a threshold is met) or batch classification against a small labelled set with low-confidence cases routed to an instruct model.

## How it scales

Requests join a queue in Postgres. Each worker loads one model at a time and serves whichever model has the deepest queue, and claims use `SELECT ... FOR UPDATE SKIP LOCKED`, so adding workers is safe. Adding a GPU host adds a worker, and applications see more throughput with nothing else changed.

That design lets a fleet of agents or several applications share a single local GPU. It also sets the limit: a single chat model under heavy concurrent load is the case vLLM's continuous batching handles better, and [how to self-host an LLM](/library/63-private-inference-stack.html) compares the two.

## Where it runs

| Deployment | Database | Workers | Outputs |
|---|---|---|---|
| Laptop or home box | Bundled Postgres | The local GPU or CPU | The cache directory |
| Shared database | Any Postgres 17 | Any host that reaches the database | The cache directory or object storage |
| Your cloud account | AWS RDS or Azure Database for PostgreSQL | GPU instances in your account | S3 or Azure Blob Storage |

On your own premises, a [private AI server](/library/117-private-ai-server.html) runs the whole stack. In a cloud account it sits inside the network rules and access controls you already operate.

## Status

Marigold is at an early stage. Interfaces, configuration and the CLI may change between releases, and the source, issues and documentation are public on [GitHub](https://github.com/bayinfosys/marigold) and [marigold.run](https://marigold.run/docs/). Benchmarks with full telemetry are on its [build log](https://marigold.run/blog.html), and the running cost of one is measured in [what self-hosted inference costs](/library/95-private-inference-costs.html).

An inference API that runs on your own hardware turns the model into infrastructure you hold, with the applications free to change around it. (Bay Information Systems deploys Marigold on clients' servers and cloud accounts; see [sovereign and on-premise AI](/sovereign-ai.html).)
